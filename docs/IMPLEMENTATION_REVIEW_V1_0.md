## Исправления текущей ветки

- Системные уведомления получают только общий текст и количество заказов;
  маршрут, телефон, имя и комментарий не читаются кодом уведомлений.
- Оба HTTP-клиента используют единую политику HTTPS для точного backend origin.
  Запрещены другие хосты, порты, userinfo, redirects и транспортные повторы.
  Это предотвращает пересылку тела login/refresh по 307/308 и повтор rotating refresh.
  Допускаются TLS 1.2/1.3 через штатную проверку сертификатов; TLS-проверка не отключалась.
- Защищены login, список и детали заказа через FLAG_SECURE.
- Отключены backup и device transfer всех app storage domains;
  пароль исключён из сохранения состояния View.
- В FCM и installation ID используется каноническая проверка UUID.
- Конфигурация Firebase, service-account файлы и signing keys исключены из Git.

## Проверки и пределы результата

- 10 JUnit-тестов реальных Java-классов политики endpoint, UUID, DriverSession и SecureHttpClient:
  PASS, javac `--release 11`, JDK 25.0.3 и JUnit 4.13.2.
- 6 offline-проверок Android XML и исходников: PASS,
  `python3 tools/check_security.py`. Это проверки конфигурации, не runtime-тесты Android.
- Существующий `uber-v3` `npm test` (26 наборов) завершился успешно; production не вызывался.
- `git diff --check`: PASS на момент проверки.
- Полная сборка, Android lint, Android unit/instrumentation и E2E не подтверждены.
  Статус попыток записывается в журнал. Успех JVM-проверок не заменяет сборку APK.
- Runtime-проверки на устройстве обязательны: screenshot/recents, backup/restore,
  уведомления с тестовыми PII, отсутствие автоматического POST replay,
  logout/refresh race и отказ при изменении назначения.
- Проверка известных CVE всех транзитивных зависимостей и SBOM ещё не завершены.
  Скрипт source guards не является полноценным secret scanner или pentest.
- Чувствительные новые функции и выпуск APK блокируются до подтверждения
  серверных контрактов, Firebase-конфигурации и необходимых проверок.
