# G2: карточка классификации Admin

Первый Android-срез утверждённого Admin classification UI после backend PR №43: строгие DTO и чтение текущего результата/истории. Ветка `arch/g2-admin-classification-read` от проверенного required-color PR №16. Это карточка чтения; форма исправления параметров, исключение и управление правилами остаются следующими частями, а не выполненными функциями.

Из выбранного автомобиля в карточке регистрации открывается отдельный неэкспортируемый экран. Перед каждым чтением проверяются текущий аккаунт/сессия/grants/OWNER MFA. Требуется существующее vehicles.verify; нового права диспетчерам нет. OWNER-only phone scope по-прежнему закрывает новый экран до классификационного запроса. Права на материалы не выдаются: содержимое СТС открывается отдельно прежним механизмом карточки регистрации.

Введённые make/model/year/color и проверенные параметры показаны раздельно. Класс только серверный, readonly; candidate явно требует отдельного итогового одобрения, история не выдаётся за текущий допуск. Null year/class/legacy color остаются неизвестными. Причины имеют безопасные подписи; свободные server errors/keys/URLs/содержимое документов не отображаются. Версия результата читается как отдельная модель правила только при существующем vehicles.read; её модель не подменяет фактическую модель автомобиля. Не угадываем exception mode или причину отсутствия текущего proof по прежнему результату.

История использует server cursor, по 50 строк. Страницы привязаны к vehicle revision; scope/generation проверяет backend. Конфликт закрывает прежнюю карточку до явного обновления с первой страницы. Нет class picker, изменений данных, POST, автоматического refresh токенов или replay мутаций. Это не UI авторства правил/исключений.

FLAG_SECURE, no autofill/content capture/view-state; route extras содержат только opaque account/vehicle IDs и удаляются после открытия. Вся metadata/история/курсор/grants/запросы очищаются и отменяются на onStop; route IDs остаются только в RAM для свежего чтения onStart. Восстановленный процесс/экран без исходного контекста закрывается. MFA expiry очищает видимую карточку без нового запроса. Изменившаяся сессия не может показать старый ответ или удалить новую сессию. Нет нового хранилища/логов/дискового cache.
