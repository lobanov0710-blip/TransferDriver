# Установка Transfer Admin: подпись и предложение решения

Статус: диагностика выполнена; вариант исправления ожидает решения владельца.
Изменение applicationId, создание постоянного ключа и переустановка не выполнялись.

## Подтверждено

Владелец сообщил «Приложение не установлено» при обновлении существующего Admin.
Точный системный INSTALL_FAILED код и сертификат установленного на телефоне APK
не получены. Общий текст Android сам по себе не доказывает единственную причину.

Выданный APK относится к source d09d5f1e2d581a6c9c866c6c389f27d53a726c75,
CI44488353051; приложение устанавливалось и выполняло тесты в чистом Android35
эмуляторе. Проверены подпись V2, binary manifest и целостность файла:

| Параметр | Значение |
| --- | --- |
| Package | `ru.transferservis.admin` |
| versionCode / versionName | `1` / `1.0` |
| minSdk / targetSdk | `26` (Android8+) / `37` |
| Размер APK | `7970338` bytes |
| SHA256 APK | `15d540051d161aba7850da05cf260234354cd5b2c468b461c1ee0478cb67e10e` |
| SHA256 сертификата | `8068a87ffc8e3ab90144b578210259e9d25cfde8c03c4088cae72c3a01f8e586` |
| testOnly | отсутствует |
| Native ABI restriction | нет native `.so` библиотек |

Сравнён прежний проверенный APK CI44321910346: тот же package/minSdk,
сертификат `eace64215fae80e931edeae5dbef56d49382e1fe44c986f40b3679416ef1bcfd`.
Это сравнение двух выданных файлов, не чтение сертификата с телефона.

Workflow каждый раз генерирует новый независимый Admin debug keystore.
Совместимость такого файла с установленной телефонной версией не обеспечена.
Если на телефоне стоит предыдущая CI-сборка с другим ключом, обычное обновление
новым APK невозможно. Смена подписи не исправляется увеличением versionCode.
Приватный ключ невозможно восстановить из публичного сертификата APK.
Правила обновления: [Android app signing](https://developer.android.com/studio/publish/app-signing).

Выдача очередного ephemeral CI APK как удобного телефонного обновления была
недоработкой процесса доставки. Проверки эмулятора/подписи не являются проверкой
обновления конкретной установленной версии; прежний receipt этого не утверждал.

## Варианты для решения владельца

| Вариант | Конкретное предложение | Влияние на установленный Admin |
| --- | --- | --- |
| A, рекомендуется для тестов | Отдельный пакет `ru.transferservis.admin.qa`, имя `Transfer Admin QA`, только STAGING; постоянный отдельный приватный QA signing key | Установка рядом; прежнее приложение и его локальные данные сохраняются |
| B | Оставить `ru.transferservis.admin`; подготовить постоянную приватную Admin-подпись и отдельно согласовать разовую переустановку | При отсутствии исходного ключа старую установку придётся удалить; потеряются её локальные сессии/настройки |

Если исходный приватный ключ установленного APK всё же сохранён в защищённом
источнике владельца, сначала проверяется его публичный certificate fingerprint:
может оказаться возможным обычное обновление. Ключ/пароли в чат не передаются.
Отсутствующий старый ключ не заменяется обходом проверки подписи Android.

## Предлагаемый объём A, ещё не утверждён

- Отдельный phone QA variant с указанными package/именем, фиксированным STAGING
  endpoint и `debuggable=false` в выдаваемом телефонном артефакте. Основной Admin
  package, Driver и их подписи не меняются.
- Постоянный QA-ключ создаётся владельцем в Windows PowerShell и хранится вне
  Git/общего workspace, с зашифрованной резервной копией и отдельным паролем.
  Ключ не публикуется в CI artifacts и не присылается в чат. Это отдельный
  Admin QA key, а не Driver upload key из RELEASE_SIGNING_OWNER_SETUP.md.
- Подготовить unsigned QA APK и безопасную локальную подпись у владельца.
  Пароли вводятся интерактивно; перед подписью проверяется SHA256 исходного APK,
  после — сертификат/подпись/хеш. Для будущих обновлений тот же ключ и возрастающий
  versionCode. Ephemeral CI APK перестаёт выдаваться как телефонное обновление.
- Проверить установку рядом, отдельные UID/хранилища, обновление QA тем же ключом,
  отказ чужой подписи, STAGING endpoint/флаги/manifest, отсутствие изменения
  установленного основного Admin. Дополнить существующие build/lint/тестовые gates.
- Приватная настройка ключа требует участия владельца на его Windows. Настройку
  подготовить после выбора варианта; сейчас новый ключ не создан.

Ни один вариант не меняет существующий OWNER account/TOTP/MFA и не расширяет
утверждённую OWNER-phone allowlist. Новые operational API на STAGING этим
предложением не активируются. Driver G1 остаётся на паузе; нет merge/deploy,
remote migration/seed, Google Play release или публикации приватных ключей.

## Основание для остановки зависимых изменений

Главное [правило владельца, AGENTS.md](../AGENTS.md), пункт3:
«Не выполнять предложенный вариант до утверждения и не искать обход требования».
Новый QA applicationId ещё не утверждён; удаление установленного приложения и
потеря его локальных данных также не разрешены. Поэтому подготовлено конкретное
предложение, а runtime/signing/package изменения ожидают решения владельца.
